# 第二批侧面数据图像规格与黑边分析

## 结论

第二批706张PNG全部是纵向侧位片，但并不是完全统一的图像规格：共有292种分辨率，宽高比从
0.238到0.512。主规格是1536×4352，共384张（54.4%）。

数据中确实存在黑边，但主要是少数来源产生的上下对称黑边：

- 144张（20.4%）检测到至少一行/列连续边缘黑像素，其中多数只是很薄的边线；
- 43张（6.1%）至少一侧黑边达到该方向尺寸的1%，定义为“明显黑边”；
- 26张（3.7%）上下或左右黑边合计达到10%，定义为“严重黑边”；
- 上、下各有42张明显黑边；左侧只有1张，右侧0张；
- 最大样本上方约16.4%、下方约16.5%，合计约32.9%的画布为空黑区域。

因此黑边不是大多数图像的通用问题，但它与数据来源高度相关，可能成为模型识别来源的捷径。

## 数据与方法

分析对象是：

```text
/Volumes/E/spine_data/20260903-侧面数据第二批/labelme-export/P202607076308
```

过滤全部 `._*` AppleDouble辅助文件后，对706张真实PNG逐图只读分析。分辨率和颜色模式直接读取
PNG IHDR；像素外观由FFmpeg将原图按宽256等比例缩小为8位灰度图后统计。

黑边判定规则：

- 灰度值不超过5视为近黑像素；
- 一行或一列中至少98%的像素近黑，才视为黑色边缘线；
- 从上、下、左、右边缘向内计算连续黑线；
- 单侧占原方向尺寸至少1%定义为明显黑边；
- 上下合计或左右合计至少10%定义为严重黑边。

像素宽度是按缩小图比例反算的近似值；比例与分层结论比单个像素数更可靠。最大黑边、无黑边、
唯一左边框和典型来源样本均已肉眼复核，自动结果与视觉一致。

## 通道与灰度

- 391张（55.4%）是8-bit灰度PNG；
- 315张（44.6%）是8-bit RGBA PNG；
- 全部315张RGBA的alpha通道逐图检查后均为255，即完全不透明；
- RGBA没有提供透明度信息，训练加载时统一解码为三通道即可。

通道格式也与来源相关。例如FQSY、LFPY、PYGZ、THBZ均为灰度，FZBW、GZLL、LFDS、WFSY、
WZH等主要或全部为RGBA。虽然Ultralytics/OpenCV通常会统一解码成三通道，仍应避免在自定义加载器
中让灰度和RGBA走不同归一化路径。

## 对训练的影响与建议

1. 不要拉伸到固定宽高。当前训练使用保持比例的YOLO letterbox和 `rect=True` 是正确的；直接把所有
   图像强制变成1280×1280会扭曲椎体形态和终板角度。
2. 当前数据可以直接作为基线训练。明显黑边只占6.1%，不会让标签失效，也没有必要因此隔离这些病例。
3. 若追求跨医院/设备泛化，建议下一版转换时只裁掉“连续且单侧≥1%”的明确黑边，并同步变换所有
   关键点和bbox。不能只裁图片而不改标签，也不要按普通暗背景做内容裁剪。
4. 26张严重黑边图裁边后收益最大：在1280输入下，最大病例约三分之一纵向像素被空画布占用，裁边可
   提高有效脊柱分辨率。
5. 黑边和来源高度相关。评估时除总体指标外，建议按来源统计关键点误差，确认模型没有依赖LFDS/GZLL/
   LWSY等来源特征。
6. 统一使用OpenCV/Ultralytics三通道读取；RGBA的alpha全部不透明，可以安全忽略，但不要让RGBA与灰度
   使用不同的数据归一化逻辑。

当前建议先按已生成的数据完成基线训练，不立即重建数据。得到各来源验证误差后，再决定是否增加“自动
裁黑边并同步坐标”的第二组对照实验，这样可以量化裁边是否真正改善泛化。
