## 图像与来源分布

图像尺寸共有 292 种，主尺寸 1536×4352 有 384 张（54.4%）。其余图像宽度和高度变化较大，因此训练预处理应保持纵横比并 letterbox，不建议直接拉伸到方形。

文件名显示 17 个来源前缀，最大来源为 LFPY 164、THBZ 141、LWSY 80、FQSY 72。PNG 格式和来源高度绑定：

- FQSY、LFPY、PYGZ、THBZ 全部是 8-bit 灰度 PNG。
- FZBW、GZLL、LWSY、WFSY、WZH 等全部或几乎全部是 8-bit RGBA PNG。

这意味着模型可能利用通道、黑边、裁切、对比度等来源特征。建议在解码后显式转换为统一灰度或 RGB，并按患者和来源分组拆分 train/val/test；验证集与测试集应报告分来源指标。

## 与当前仓库流水线的兼容性

当前 `2-build_dataset/convert_to_yolo_pose.py`：

- 假设“每个样本一个子目录”，而本批次是单层 PNG/JSON 平铺。
- class map 只有 C7、T1-T12、L1-L5 共 18 类，会静默丢弃 C2-C6。
- 显式排除 S1，并且只处理 polygon，因此不会使用本批次的 S1 line。

当前 `2-build_dataset/convert_to_yolo_cfh.py` 和 CFH detection 转换只识别 `CFH`，直接使用本批次时只能利用 239/706（33.9%）图像的股骨头标注，另外 467 张会因使用 FH 双点或无标记而被跳过。

因此，不建议直接把这批数据接到现有转换脚本。应先确定新任务类别范围和股骨头目标定义，再为平铺数据增加明确的转换逻辑和转换后统计校验。

## 建议的入库顺序

1. 建立人工复核清单：16 个核心标签不完整样本、T1/T2 疑似互换样本、C2 轻微越界样本。
2. 决定是否训练 C2-C6，以及 S1 line 是否作为独立任务或转换成统一表示。
3. 确认 `FH-1`/`FH-2` 到 `CFH` 的业务规则；若允许，统一为两点中点并保留原始点作追溯。
4. 解码后显式统一为灰度或 RGB，去除 alpha 的不确定行为；保持纵横比进行 resize/letterbox。
5. 排除 `._*` 文件；转换后再次检查图像/标签数量、类别计数、归一化坐标范围和空标签文件。
6. 按患者标识与来源前缀分组拆分，避免同患者或同源近重复进入不同集合，并报告分来源性能。
