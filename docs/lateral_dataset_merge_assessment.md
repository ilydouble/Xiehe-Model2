# 新旧侧面数据集合并评估

评估日期：2026-09-07

## 结论

可以统一成一个大数据集，但推荐统一成当前模型使用的 **18 类椎体四角点任务**：

`C7, T1-T12, L1-L5`

不建议直接合并文件夹，也不建议在现有 `datasets/yolo_corner` 上追加新数据。应从两批原始 LabelMe 重新构建统一 manifest、严格按图像/JSON 同 stem 配对、统一四角点顺序、统一图像通道，并按患者重新拆分 train/val/test。

当前可得到约 **1,056 张结构完整的唯一候选图像**：旧批 356 张、新批 700 张。新批 700 张中有 1 张已知 T1/T2 疑似互换，修正后可使用；若完全不改标注，保守使用 1,055 张。修复旧批 1 张和新批 6 张共同类别不完整样本后，上限约 1,063 张。

## 为什么只能“规范化后合并”

### 1. 同名 C2 的语义冲突

旧数据的 `C2` 是骨盆区 circle，和 `C1` 一起表示两个股骨头辅助圆；新数据的 `C2` 是颈椎 C2 四点 polygon。两者同名但完全不同义。

如果直接按 label 字符串合并，C2 类会同时包含股骨头与颈椎，造成严重标签污染。

推荐方案是当前 18 类任务直接过滤旧 C1/C2 circle和新 C2-C6；如果未来要训练 C2-C6，必须补标旧批颈椎，不能把旧批未标的可见 C2-C6 当成背景加入完整检测任务。

### 2. polygon 标注方式不同

旧批为椎体密集轮廓，新批为四角点 polygon。对当前 YOLO pose 任务可统一为四点：

- 旧批：从密集轮廓提取四个角点。
- 新批：保留原四点，但按同一规则重新排序。
- 两批共同使用明确的角点顺序，例如左上、右上、右下、左下，并做可视化抽查。

若目标是语义分割，两批暂时不应直接合并，因为密集轮廓与四边形的边界精度不同。

### 3. 股骨头标注体系不同

旧批 CFH 是单点；新批既有 CFH，也有 FH-1/FH-2 两个点。旧批 18 个同时含 C1、C2、CFH 的样本显示：两个股骨头圆心中点距 CFH 中位仅 5.88 px；新批 CFH 与 FH 双点中点的归一化位置分布也高度一致。

因此可把 `FH-1` 与 `FH-2` 的中点转换成 CFH，但应先由业务侧确认两点确实是两个股骨头中心。转换后理论上可获得约 1,068 个带 CFH/FH 信息的原始标注样本，具体训练池还要按图像配对、去重和任务完整性筛选。

### 4. 图像通道和来源域不同

旧批 PNG 全为灰度，新批同时存在灰度和 RGBA，而且新批通道格式几乎由来源决定。必须在训练 loader 中显式统一为灰度或 RGB，去掉 alpha 的不确定行为，并保持纵横比进行 resize/letterbox。

否则模型可能学习医院来源、黑边、通道或裁切差异，而不是椎体结构。

## 不能直接沿用现有 `yolo_corner`

旧转换器按患者目录读取第一个 JSON，然后把该标注应用于目录内全部 PNG。严格核对发现：

- 旧 353 个已选患者目录内有 358 对真正同 stem 的 PNG/JSON。
- 另有 10 张 PNG 没有同 stem JSON，但仍进入了现有 368 张 YOLO 图像，存在套错标注风险。
- 1 对严格配对图像缺共同 18 类。
- 1 组旧 PNG 完全重复。
- 现有368张图可精确映射回353个原始患者目录，其中4个患者跨越train/val/test，已经形成患者级泄漏。此前仅按姓名前缀曾把两个不同患者ID的同名YANG_YI合并，现已按原始目录ID纠正。

所以应从原始 LabelMe 重建，不能把旧 YOLO 标签当作合并基线。

## 推荐的统一数据规范

每张影像建立一条 manifest 记录，至少包含：

| 字段 | 含义 |
|---|---|
| `sample_id` | 全局唯一样本 ID，建议包含 batch 前缀 |
| `patient_id` | 患者分组 ID |
| `source_batch` | `LAT202511` 或 `LAT20260903` |
| `source_site` | 新批文件名前缀或旧批来源标识 |
| `image_path` | 原始图像路径 |
| `annotation_path` | 与图像同 stem 的 JSON 路径 |
| `label_profile` | 18 类、CFH、FH 双点、S1 等可用情况 |
| `image_mode` | 灰度或 RGBA/RGB |
| `split_group` | 默认等于 patient_id |
| `qc_status` | pass、needs_review、excluded |

建议为原始 LabelMe 建立不可变数据层，再生成面向具体任务的派生数据集，而不是破坏或覆盖原标注。

## 推荐构建流程

1. 扫描两批原始目录，排除 `._*`、无同 stem JSON 的 PNG 和非目标视图。
2. 建立统一 manifest，并为样本 ID 加 batch 前缀，避免文件名冲突。
3. 只选择共同 18 类完整样本；修订新批 T1/T2 疑似互换样本。
4. 旧密集 polygon 与新四点 polygon 使用同一角点提取/排序函数，生成 YOLO pose 标签。
5. 转换后检查类别数、每图对象数、关键点坐标范围、角点顺序和空标签文件。
6. 对图像显式统一通道，保持纵横比 letterbox。
7. 对同患者、完全重复和近重复影像分组；按患者一次性拆分 train/val/test。
8. 在患者分组基础上，再按 batch、来源站点和图像模式做分层平衡。
9. 分别报告旧批、新批及不同来源站点的验证指标，确认模型没有只学习来源域。

## 建议保留的任务边界

- 主椎体 pose 数据集：C7、T1-T12、L1-L5，共 18 类。
- 股骨头任务：统一为 CFH 单点，可作为独立模型或合并到 pose 类别。
- C2-C6：暂时仅保存在新批 canonical 标注中，不进入旧新混合训练，除非补标旧批。
- S1：当前继续排除；若未来使用，需要把旧批 line/polygon/circle 与新批 line 统一定义。
- T13、L6：作为解剖变异标签保留在 canonical 层，默认不进入 18 类任务。

## 最终判断

**可以合并，而且推荐合并。** 对当前 18 类四角点模型，两批共享相同的主要解剖标签，数据规模可从现有 368 张 YOLO 图像提升到约 1,056 张经过严格配对和去重的候选图像。

合并的前提是：从原始 LabelMe 重建、统一四角点语义与顺序、统一图像通道、修复已知异常，并按患者重做 split。直接复制文件或追加现有 YOLO 数据会引入 C2 同名异义、错误标注和患者泄漏。
